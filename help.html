Install the desktop app

The desktop app holds the page and the LED helper in one program. On the lab computer it's the easiest way to run Bee Tracker; for tracking saved videos only, the web page is enough.

  1. Download BeeTracker.exe (Windows) or BeeTracker.dmg (Mac) from the latest release.
  2. For LEDs (Windows only): install NI's NI-DAQmx driver from ni.com, restart, and plug in the USB-6003 before starting the app.
  3. First start: the app isn't code-signed. On Windows choose More info → Run anyway. On a Mac, drag it to Applications, open it, then allow it under System Settings → Privacy & Security → Open Anyway.
  4. The page opens in Chrome or Edge, already connected to the LEDs. A small Bee Tracker window shows the DAQ, with Open Bee Tracker, LEDs off and Quit. Keep it open while you work; quitting turns both LEDs off.

If the small window says the LEDs are simulated, it says why, with a Copy this message button. See Troubleshooting.

Update to a new version

The app doesn't update itself. To update: save a project file (Data tab), quit Bee Tracker, end any leftover BeeTracker processes in Task Manager, then replace the old BeeTracker.exe with the one from the latest release. Your recordings and settings stay: they are kept in the browser, not in the app.

The web page at this address is always the newest version.

Quick start

  1. Fill in your initials and the experiment at the top. Choose Live camera and press Start camera (or Saved video and open a file).
  2. Setup tab: press Draw arena and drag around the arena floor. Enter its real width in mm and the number of bees.
  3. Optional: Add zone, and an edge band in mm.
  4. Detect tab: with the bees in, press Set up detection. Wait for Found all … bees. Ready to track.
  5. Optional: LEDs tab: connect, check the protocol, press Test LEDs (5 V).
  6. Under the video, set the Length and press Start trial (saved video: Track bees). Keep the tab in front.
  7. Read the results; Data tab: save the CSVs and the project file.

Several cameras

Under Live camera, set Cameras to 2, 3 or 4, choose a layout (side by side, stacked or 2 × 2) and a camera for each tile, then press Start camera. The cameras are joined into one image, and everything else works on it as if it were one camera, including the saved trial video.

  • Set each tile's zoom so 1 mm spans the same number of pixels in every tile; otherwise distances across tiles are off.
  • Tiles are at most one frame apart (33 ms at 30 fps).
  • Two USB cameras usually work on one computer. With more, use separate USB ports; the page warns if the frame rate drops.

Linked arenas

For a bee that moves between arenas, for example through a tunnel between two arenas filmed by two cameras:

  1. Draw the arena around the whole image.
  2. Draw each real arena as a zone, click its outline, and tick Arena area in the bar under the video.

The results add Crossings, Transit s (time between leaving one arena and arriving in the next) and the first crossing. They are also in the CSVs, Compare recordings and the PER Scorer export (In transit). Distances between bees count only bees in the same arena.

Detection

Set up detection gets a picture of the arena without bees (the background), then chooses whether bees are darker or lighter, a threshold above the camera's noise, the size of one bee, and a processing size. Every value is under Advanced, tagged auto; change one and it is tagged set by you and kept. Reset all to auto undoes that.

Best background: before the bees go in, use Capture empty arena (Advanced), and choose it for Set up detection gets the background by.

LED protocols

With the live camera, each trial can play a light protocol on the USB-6003's two outputs (AO 0, AO 1). A protocol is a list of segments; each sets what both LEDs do: off, a constant level, a ramp, an exponential, a sine, a pulse train, a single pulse, random levels, or a formula of time. Protocols can repeat and shuffle.

  • Test LEDs (5 V) turns each output on at 5 V for 1 s, to check the wiring.
  • Tick LEDs in the trial bar to play the protocol with a trial; it plays on the DAQ's own clock.
  • Results and charts are also split by LED condition (the segment labels).
Levels can go up to 10 V. Keep every level within what your LED driver and LED can take.

Wiring the LEDs

Each output gives a voltage against the shared AO GND, so every circuit returns to AO GND. The outputs give only about 5 mA: drive each LED through a driver whose current follows the voltage. The cheapest is an op-amp current sink on a breadboard: an LM358, a logic-level MOSFET (IRLZ44N) and a 1 Ω resistor. LED current = control voltage / 1 Ω, so brightness follows the protocol exactly, without flicker.

FromTo
5 V supply + / −Breadboard red (+) and blue (−) rails
DAQ AO GNDBlue rail (shared ground)
DAQ AO 015 kΩ to LM358 pin 3 (+ input); 1 kΩ from pin 3 to the blue rail
LM358 pin 1 (output)100 Ω to the MOSFET gate
MOSFET sourceLM358 pin 2 (− input), and 1 Ω to the blue rail
MOSFET drainLED − (cathode); LED + to the red rail
LM358 pins 8 / 4Red rail / blue rail, with 0.1 µF between them
Second LEDSame circuit on AO 1, using pins 5, 6 and 7

With these values 5 V gives 312 mA (10 V would give 625 mA). Use a 5 V supply, not 12 V: the MOSFET turns any extra voltage into heat. A Mean Well LDD-H is on/off only (its DIM input switches and dims by PWM, which bees can see as flicker); use it only for fixed-brightness on/off protocols.

Results and exports

MeasureMeaning
FoundShare of samples the bee was detected in (below 80% is flagged)
Distance, speed, movingFrom the smoothed track; moving = faster than 3 mm/s
Zones, edgeShare of time in each zone (visits in brackets), and near the wall
Nearest, near bee, encountersTwo or more bees: distance to the nearest bee, share of time within 10 mm of another, separate contacts
Crossings, transitLinked arenas: moves between arenas and time between them

Beside the track map, charts show each bee's distance from a zone and the distance between bees over time; point at a chart to see where each bee was. With unmarked bees that touched, use the All bees row: identities can swap.

Data tab: Tracks CSV (every sample), Summary CSV (one row per bee), Export to PER Scorer, LED CSVs, and Save project (.json). Save the project at the end of every session.

Troubleshooting

ProblemWhat to do
LEDs say simulatedThe app says why. Isn't installed: install NI-DAQmx and restart. No NI device: plug in the DAQ, then restart the app. On a Mac the LEDs are always simulated.
Can't reach the LED helperThe web page can't start it. Use the desktop app, or run py helper\led_helper.py and type its code.
Camera won't startAllow the camera in the address bar; close other programs using it; with several cameras, try other USB ports or a smaller size.
Set up detection finds too many or too few beesTurn on Show detection. Shadows or reflections: fix the light or raise the threshold (Advanced). Too few: bees touching, or a still bee became background: use Capture empty arena.
Tracking didn't keep upLower the processing size or samples per second (Detect → Advanced), or a smaller camera size.
Distances in pxEnter the arena's width in mm on the Setup tab.
Recordings disappearedBrowser storage was cleared, or you opened the other copy (app vs web page each keep their own). Use Open project… with your saved file.

Still stuck? Report it on GitHub Issues, with the app's message copied in.
